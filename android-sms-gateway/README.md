# پیامک‌یار الوشمال (Alooshomal SMS Gateway)

اپ اندروید مستقل برای فروشندگان الوشمال. این اپ پیامک‌های **واریز بانکی** را
روی گوشی فروشنده می‌خواند، تراکنش را به API الوشمال می‌فرستد و اگر مبلغ و
چهار رقم آخر کارت مقصد با سفارش کارت‌به‌کارتِ در انتظار پرداخت بخواند، پرداخت
را خودکار تأیید می‌کند. روش دستی ارسال رسید در پنل همچنان فعال است.

این پوشه کاملاً از مونوریپوی اصلی جدا است:

- در `docker-compose`، `install.sh` و workflow استقرار استفاده نمی‌شود.
- هیچ فایلی از آن روی سرور کپی یا deploy نمی‌شود.
- فقط از API موجود (`/api/sms-gateway/...`) استفاده می‌کند.

## قابلیت‌ها

- اتصال امن با کد یک‌بارمصرف از پنل کسب‌وکار (توکن دستگاه رمزنگاری‌شده روی گوشی).
- خواندن پیامک واریز در پس‌زمینه با `BroadcastReceiver` + `WorkManager`
  (بدون سرویس دائمی و بدون مصرف باتری زیاد).
- پارس محافظه‌کارانه‌ی پیامک بانک‌های ایرانی (مبلغ ریال/تومان، کارت مقصد،
  شماره پیگیری، نام بانک).
- ارسال idempotent (تکرار پیامک، تراکنش تکراری نمی‌سازد).
- همگام‌سازی پیامک‌های ۴۸ ساعت گذشته پس از اتصال (با اجازه‌ی `READ_SMS`).
- ضربان دوره‌ای (هر ۶ ساعت) تا پنل فروشنده «آخرین اتصال» دستگاه را همیشه
  تازه نشان دهد، حتی وقتی اپ باز نشده است.
- اعلان نتیجه: تأیید خودکار / نیاز به بررسی در پنل.
- رابط فارسی و راست‌به‌چپ، بدون تبلیغات، بدون ردیابی و بدون دسترسی اضافی.

## پیش‌نیاز ساخت

- JDK 17
- Android SDK Platform 35 و Build-Tools 35.0.0
- Gradle 8.11 — یا فقط استفاده از `./gradlew` (wrapper در مخزن هست و خودش
  نسخه‌ی درست را می‌آورد).

در این محیط، `local.properties` به SDK محلی اشاره می‌کند و در git نیست.

## ساخت خروجی

```bash
cd android-sms-gateway
./gradlew :app:assembleRelease
```

خروجی:

```
app/build/outputs/apk/release/app-release.apk
```

برای ساخت نسخه‌ی debug:

```bash
./gradlew :app:assembleDebug
```

## امضای اپ و انتشار در کافه‌بازار

کلید امضا در `keystore/alooshomal-sms-gateway.jks` و رمز آن در
`keystore.properties` است. **این دو فایل را گم نکنید**؛ برای انتشار نسخه‌های
بعدی باید با همین کلید امضا کنید. پیش از انتشار عمومی، بهتر است کلید تازه با
رمز قوی بسازید و `keystore.properties` را در جای امن نگه دارید.

این دو فایل به‌صورت عمدی در `.gitignore` هستند و در مخزن کامیت نمی‌شوند؛
آن‌ها فقط روی همین دستگاه/نسخه‌ی پشتیبان امن نگه داشته می‌شوند.

چک‌لیست کافه‌بازار:

- `applicationId` یکتا: `ir.alooshomal.smsgateway`
- `targetSdk = 35`، `minSdk = 26`
- APK امضاشده‌ی release (نه debug)
- توضیح شفاف دسترسی `READ_SMS`/`RECEIVE_SMS` در فرم انتشار و متن
  [PRIVACY.md](PRIVACY.md)
- آیکون، نام و اسکرین‌شات فارسی
- اعلام اینکه اپ فقط برای فروشندگان متصل به پنل الوشمال است

## اتصال به پنل

1. در پنل کسب‌وکار: «کارت به کارت» ← «اتصال اپ اندروید و تأیید خودکار با
   پیامک بانکی».
2. شماره کارت کسب‌وکار باید از قبل ثبت و فعال شده باشد.
3. «ساخت کد اتصال» را بزنید؛ کد ۸ کاراکتری و آدرس سرور را در اپ وارد کنید.
4. دسترسی پیامک را بدهید. اپ پیامک‌های ۴۸ ساعت گذشته را هم بررسی می‌کند.

## قرارداد API

همه‌ی پاسخ‌ها در پوشش `{ success, data }` برمی‌گردند.

| متد | مسیر | احراز هویت | کار |
| --- | --- | --- | --- |
| `POST` | `/api/sms-gateway/device/pair` | کد یک‌بارمصرف | دریافت توکن دستگاه |
| `GET` | `/api/sms-gateway/device/me` | Bearer device token | کارت، کسب‌وکار و سفارش‌های در انتظار |
| `POST` | `/api/sms-gateway/device/transactions` | Bearer device token | ثبت واریز و تطبیق خودکار |
| `POST` | `/api/sms-gateway/device/heartbeat` | Bearer device token | زنده‌بودن دستگاه |

سمت پنل:

- `GET /api/sms-gateway/overview`
- `POST /api/sms-gateway/pairing-code`
- `DELETE /api/sms-gateway/devices/:id`
- `GET /api/sms-gateway/transactions`
- `GET /api/sms-gateway/transactions/:id/candidates`
- `POST /api/sms-gateway/transactions/:id/link`
- `POST /api/sms-gateway/transactions/:id/rematch`
- `POST /api/sms-gateway/transactions/:id/ignore`

## محدودیت‌ها

- قالب پیامک بانک‌ها متفاوت است. پارسر فقط پیامک‌هایی را می‌فرستد که نشانه‌ی
  «واریز» دارند و مبلغ و کارت مقصد را بتواند بخواند. پیامک‌های مبهم در پنل
  به‌صورت «بدون سفارش» می‌آیند و با تطبیق دستی حل می‌شوند.
- تطبیق خودکار فقط وقتی انجام می‌شود که **دقیقاً یک** سفارش کارت‌به‌کارت با
  همان مبلغ و در ۷ روز گذشته در انتظار پرداخت باشد. اگر چند سفارش هم‌مبلغ
  باشد، برای جلوگیری از اشتباه، تطبیق دستی لازم است.
- واریز باید به همان کارتی باشد که در پنل ثبت شده است (چهار رقم آخر باید
  بخواند).

## تست دستی

در پنل یک سفارش کارت‌به‌کارت با مبلغ مشخص بسازید و آن را تأیید کنید. سپس
پیامکی شبیه نمونه‌های [SAMPLE-SMS.md](SAMPLE-SMS.md) را با یک اپ پیامک‌رسان
یا `adb emu sms send` به گوشی بفرستید. باید در پنل، تراکنش «تأیید خودکار»
شود و سفارش به `PAID` برود.
