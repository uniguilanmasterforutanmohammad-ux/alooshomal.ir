# پایگاه داده: اسکیمای Prisma، ایندکس‌ها و پاک‌سازی

این سند قواعد نگه‌داری دیتابیس را جمع می‌کند تا تغییرات بعدی هم‌سبک و قابل
مقیاس بمانند.

## منبع حقیقت

- مدل‌ها در `apps/api/prisma/schema.prisma` هستند و با `prisma db push` اعمال
  می‌شوند (پروژه از مهاجرت‌های Prisma استفاده نمی‌کند).
- `apps/api/docker-entrypoint.sh` پیش از هر `db push` در صورت تغییر اسکیما
  snapshot می‌گیرد و اگر SQL شامل `DROP TABLE/COLUMN` باشد، بدون
  `ALLOW_DESTRUCTIVE_DB_PUSH=1` متوقف می‌شود.
- چیزهایی که Prisma نمی‌تواند بیان کند (افزونه‌ی `pg_trgm`، ایندکس‌های GIN و
  ایندکس‌های جزئی) در `apps/api/prisma/bootstrap.sql` و به‌صورت idempotent
  اجرا می‌شوند.

## سیاست ایندکس

هر ایندکس هزینه‌ی نوشتن و فضای دیسک دارد؛ فقط ایندکسی بسازید که یک کوئری واقعی
از آن سود می‌برد:

- **یکتایی**: `@unique` خودش یک ایندکس یکتا می‌سازد. `@@index` روی همان فیلد
  تکراری است و باید حذف شود.
- **فهرست‌های «مال من»**: کوئری‌های `where: { userId }` + `orderBy: { createdAt }`
  با ایندکس مرکب `[userId, createdAt]` پوشش داده می‌شوند (نه دو ایندکس تک‌ستونی).
- **کلید خارجی**: Postgres به‌طور خودکار روی FK ایندکس نمی‌سازد. فقط FKهایی را
  ایندکس کنید که در `where`/`join` واقعی استفاده می‌شوند؛ FKهای صرفاً حسابرسی
  (مثل `decidedById`) نیازی ندارند.
- **جست‌وجوی متنی عمومی**: `ILIKE '%term%'` روی دایرکتوری با ایندکس‌های GIN
  `gin_trgm_ops` در `bootstrap.sql` پوشش داده می‌شود.
- **مرتب‌سازی پیش‌فرض دایرکتوری**: ایندکس مرکب
  `(status, isPublished, pinnedAt DESC, id DESC)` در `bootstrap.sql`.

### تغییرات انجام‌شده در پاک‌سازی

- حذف ایندکس‌های تکراری روی `users.email`، `users.phone`، `cities.name`،
  `business_categories.name`، `news_categories.name`، `biolinks.slug` و
  `business_cards.slug` (همه از قبل `@unique` داشتند).
- تبدیل ایندکس‌های تک‌ستونی `userId` به مرکب `[userId, createdAt]` در جدول‌های
  پرداخت/فهرست (اشتراک، خدمت، کیف پول، درخواست، امتیاز، ماژول، تیکت و درخواست
  تغییر پروفایل) و `[customerUserId, issuedAt]` برای فاکتورها.
- مرکب‌کردن ایندکس خرید ماژول به `[workspaceId, status, moduleKey]` تا کوئری
  بسته‌های پولی هر فضای کسب‌وکار از یک ایندکس استفاده کند.

## بررسی سلامت (read-only)

```bash
npm run db:audit          # یا: python3 scripts/db_audit.py
python3 scripts/db_audit.py --no-fail   # فقط گزارش، بدون خروج غیرصفر
```

اسکریپت هیچ داده‌ای را تغییر نمی‌دهد و این موارد را بررسی می‌کند:

- هر پرداخت `PAID` (اشتراک، خدمت، کیف پول، پله/تبلیغ، ماژول) فاکتور دارد
  (قانون ۱۱ در `AGENTS.md`).
- جمع فاکتور (`subtotal + tax = total`) و جمع اقلام با مبلغ فاکتور می‌خواند.
- موجودی `user_wallets` با جمع `wallet_entries` می‌خواند.
- ردیف‌های یتیم در بیولینک، کارت ویزیت، پست فید، نشست و آیتم فاکتور.
- اسلاگ خالی، کارت واردشده‌ی منتشرشده، کد ملی نامعتبر، منبع ناشناخته در فاکتور
  و پست فید با تگ ناقص.
- تعداد نشست‌های مرده (منقضی/بیکار/بازپس‌گرفته‌شده).

خروجی غیرصفر فقط وقتی است که یک بررسی **بحرانی** شکست بخورد؛ برای CI مناسب است.

## پاک‌سازی دوره‌ای

- `ActivityRetentionJob` لاگ‌های سیستم را طبق پنجره‌ی تنظیم‌شده‌ی ادمین روزانه
  هرس می‌کند.
- `SessionsCleanupJob` روزانه نشست‌های مرده را حذف می‌کند
  (`SessionsService.pruneDead`): منقضی‌شده، بیکار بیش از ۷ روز، یا باطل‌شده‌ی
  قدیمی. JWT strategy از قبل همه‌ی این‌ها را رد می‌کند، پس حذف فقط فضا آزاد
  می‌کند.
- `SubscriptionsExpiryJob` ساعتی پلن‌های منقضی را به پلن رایگان برمی‌گرداند.

## مقیاس

- اندازه‌ی pool هر replica با `DATABASE_POOL_MAX` کنترل می‌شود (پیش‌فرض ۱۰)؛
  `replicas × DATABASE_POOL_MAX` باید کمتر از `max_connections` پستگرس بماند.
- صفحه‌بندی فعلی offset-based است. برای صفحه‌های خیلی عمیق، keyset/cursor
  pagination در `BACKLOG.md` ثبت شده است.
- قبل از تغییر ساختار بزرگ، `npm run db:backup` و سپس `db:audit` بگیرید.
