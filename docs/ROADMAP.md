# نقشه‌ی راه و شکاف‌های پیشنهادی

این فهرست اولویت‌دار است، نه تعهد زمانی. هر موردی که به بعد موکول شود باید طبق
قانون ۶ در `BACKLOG.md` هم ثبت شود. وضعیت‌ها: `پیشنهاد` / `در انتظار` /
`در حال انجام` / `انجام‌شده`.

## P0 — پایداری، امنیت عملیاتی و کیفیت

### ۱. تست خودکار و gate در CI — وضعیت: پیشنهاد

- **مشکل:** هیچ تست واحد/e2e در مخزن نیست؛ CI فقط typecheck/lint/قراردادها را
  اجرا می‌کند. ریفکتورهای بزرگ (مثل همین پاک‌سازی) فقط با typecheck و چند
  درخواست دستی تأیید می‌شوند.
- **پیشنهاد:** Jest + Supertest برای سرویس‌های حساس (auth، finance،
  subscriptions، wallet، onboarding) و Playwright برای مسیرهای طلایی
  (ورود، ساخت کارت، خرید اشتراک، پرداخت شبیه‌سازی‌شده). یک job در
  `.github/workflows/ci.yml` با Postgres/Redis سرویس‌های موقت.
- **اثر:** بالا / **هزینه:** متوسط.

### ۲. مشاهده‌پذیری (logs/metrics/tracing) — وضعیت: پیشنهاد

- **مشکل:** لاگ‌ها فقط `console`/Nest Logger هستند؛ شناسه‌ی درخواست، نرخ خطا و
  latency قابل ردیابی نیست. `monitoring/` فقط منابع سرور را چک می‌کند.
- **پیشنهاد:** structured JSON logging با `requestId`، اتصال Sentry (یا
  GlitchTip) برای خطاهای API/Web، و `/api/metrics` سازگار با Prometheus
  (درخواست، latency، خطا، صف‌های پرداخت).
- **اثر:** بالا / **هزینه:** متوسط.

### ۳. مهاجرت‌های نسخه‌دار Prisma — وضعیت: پیشنهاد

- **مشکل:** اعمال اسکیما با `db push` انجام می‌شود؛ تاریخچه‌ی تغییرات و
  rollback قابل بازبینی نیست (entrypoint فقط snapshot/گارد دارد).
- **پیشنهاد:** переход به `prisma migrate` برای تغییرات ساختاری، نگه‌داشتن
  `bootstrap.sql` فقط برای extension/GIN، و یک مرحله‌ی `migrate deploy` در
  استقرار.
- **اثر:** بالا / **هزینه:** متوسط.

### ۴. مدیریت و چرخش Secretها — وضعیت: پیشنهاد

- **مشکل:** همه‌ی کلیدها در `.env` سرور هستند؛ چرخش `JWT_SECRET` بدون
  `SOCIAL_CREDENTIALS_KEY` رمزهای گاوصندوق را ناخوانا می‌کند.
- **پیشنهاد:** Docker secrets یا Vault، مستندسازی چرخش کلیدها، و یک دستور
  بازرمزنگاری برای `SOCIAL_CREDENTIALS_KEY`.
- **اثر:** متوسط / **هزینه:** کم-متوسط.

### ۵. تمرین بازیابی پشتیبان — وضعیت: پیشنهاد

- **مشکل:** backup/restore پیاده‌سازی شده، اما بازیابی واقعی دوره‌ای تست
  نمی‌شود.
- **پیشنهاد:** یک job ماهانه که آخرین snapshot را در محیط staging بازیابی و
  `db_audit.py` را اجرا کند.
- **اثر:** بالا / **هزینه:** کم.

## P1 — شکاف‌های محصولی

### ۶. نمایش تبلیغ «صفحه‌ی اصلی» — وضعیت: در انتظار تصمیم محصولی

- **مشکل:** سوئیچ `featureAdRequests`، قیمت `adHomePrice` و جریان تأیید مدیر
  فعال است، اما هیچ جعبه‌ی تبلیغی در صفحه‌ی اصلی رندر نمی‌شود (کامپوننت
  بی‌ارجاع در `v4.77.4` حذف شد).
- **پیشنهاد:** یا یک جعبه‌ی سبک در خانه با داده‌ی `ads` عمومی اضافه شود، یا
  محصول «تبلیغ صفحه‌ی اصلی» از تنظیمات/قیمت‌گذاری برداشته شود.
- **اثر:** بالا (درآمد) / **هزینه:** کم.

### ۷. بازگشت وجه/اعتبار درخواست‌های پرداخت‌شده‌ی ردشده — وضعیت: معوق

- **مشکل:** اگر مدیر یک پله/تبلیغ پرداخت‌شده را رد کند، پول در سیستم می‌ماند
  و مسیر بازگشت خودکار وجود ندارد (در `BACKLOG.md` ثبت شده).
- **پیشنهاد:** واریز به کیف پول یا بازگشت از درگاه با ثبت فاکتور اصلاحی/`VOID`
  و ردیف منفی در دفتر کیف پول.
- **اثر:** بالا (اعتماد کاربر) / **هزینه:** متوسط.

### ۸. تأیید مالکیت پیش از تصاحب کسب‌وکار — وضعیت: معوق

- **مشکل:** جریان claim وجود دارد، اما تأیید مالکیت (مدرک/تماس) قبل از تصاحب
  کامل نیست.
- **پیشنهاد:** مرحله‌ی تأیید ادمین + مدرک، و جلوگیری از claim تکراری.
- **اثر:** بالا (امنیت داده) / **هزینه:** متوسط.

### ۹. تمدید خودکار/دوره‌ای اشتراک — وضعیت: پیشنهاد

- **مشکل:** تمدید دستی است؛ کاربر باید هر دوره دوباره پرداخت کند.
- **پیشنهاد:** توکن پرداخت تکرارشونده (در صورت پشتیبانی درگاه) یا یادآور
  خودکار پیش از انقضا + لینک تمدید یک‌کلیکی.
- **اثر:** بالا (درآمد) / **هزینه:** متوسط-بالا.

### ۱۰. درگاه پرداخت دوم/پشتیبان — وضعیت: پیشنهاد

- **مشکل:** فقط Payping پیکربندی شده؛ قطعی درگاه یعنی توقف همه‌ی فروش‌ها.
- **پیشنهاد:** انتزاع `PaymentGateway` و افزودن یک درگاه دوم (زرین‌پال/آیدی‌پی)
  با همان قرارداد `recordSale` و callback.
- **اثر:** بالا / **هزینه:** متوسط.

### ۱۱. اتصال فاکتور به سامانه‌ی مؤدیان — وضعیت: پیشنهاد

- **مشکل:** فاکتور داخلی کامل است، اما ارسال به سامانه‌ی مالیاتی کشور انجام
  نمی‌شود.
- **پیشنهاد:** آداپتور ارسال فاکتور/صورتحساب الکترونیکی با صف retry و وضعیت
  ارسال در پنل مالی.
- **اثر:** بالا (انطباق قانونی) / **هزینه:** بالا.

### ۱۲. داشبورد تحلیلی مالک کسب‌وکار — وضعیت: پیشنهاد

- **مشکل:** `ScanEvent`، بازدید و تعامل‌ها ثبت می‌شوند، اما مالک نمودار
  بازدید/اسکن QR/تماس/تبدیل ندارد.
- **پیشنهاد:** صفحه‌ی «آمار» در پنل کسب‌وکار با بازه‌ی زمانی و مقایسه.
- **اثر:** متوسط-بالا (ارزش اشتراک) / **هزینه:** متوسط.

### ۱۳. هشدار کمبود موجودی و سفارش‌های معطل — وضعیت: پیشنهاد

- **مشکل:** `RetailStockMovement` و سفارش‌ها وجود دارند، اما هشدار/اعلان
  خودکار برای موجودی کم یا سفارش در انتظار نیست.
- **پیشنهاد:** آستانه‌ی موجودی در محصول + اعلان در پنل و پیامک/بله.
- **اثر:** متوسط / **هزینه:** کم.

### ۱۴. یادآور پیگیری CRM — وضعیت: پیشنهاد

- **مشکل:** تعامل‌ها ثبت می‌شوند، اما یادآور «تماس بعدی» وجود ندارد.
- **پیشنهاد:** فیلد `nextFollowUpAt` + job اعلان روزانه.
- **اثر:** متوسط / **هزینه:** کم.

### ۱۵. حساب کارمند/تیم برای هر فضای کسب‌وکار — وضعیت: پیشنهاد

- **مشکل:** هر فضای کسب‌وکار یک مالک دارد؛ نقش‌های محدود فقط برای ادمین‌های
  محتوا هستند.
- **پیشنهاد:** دعوت کارمند با نقش (مدیر سفارش/پشتیبانی/فقط‌خواندنی) و
  scoping در `BusinessWorkspace`.
- **اثر:** بالا (کسب‌وکارهای بزرگ‌تر) / **هزینه:** متوسط-بالا.

### ۱۶. برنامه‌ی معرفی (Referral) — وضعیت: پیشنهاد

- **مشکل:** امتیاز و کیف پول هست، اما کد معرف/پاداش دعوت نیست.
- **پیشنهاد:** کد یکتا، ثبت در ثبت‌نام، پاداش امتیاز/کیف پول پس از اولین خرید.
- **اثر:** متوسط (رشد) / **هزینه:** متوسط.

### ۱۷. حذف حساب و خروجی داده‌ی کاربر — وضعیت: پیشنهاد

- **مشکل:** مسیر خودکار حذف/خروجی داده برای انطباق حریم خصوصی وجود ندارد.
- **پیشنهاد:** درخواست حذف با دوره‌ی نگه‌داری قانونی، ناشناس‌سازی فاکتورها و
  خروجی JSON از داده‌های کاربر.
- **اثر:** متوسط (انطباق) / **هزینه:** متوسط.

## P2 — مقیاس و تجربه

### ۱۸. صفحه‌بندی cursor/keyset — وضعیت: معوق

- **مشکل:** صفحه‌بندی offset برای صفحه‌های عمیق کند می‌شود.
- **پیشنهاد:** keyset برای فهرست‌های عمومی/زمان‌محور (دایرکتوری، فید، اعلان).
- **اثر:** متوسط / **هزینه:** متوسط.

### ۱۹. موتور جست‌وجوی اختصاصی — وضعیت: پیشنهاد

- **مشکل:** جست‌وجوی دایرکتوری با trigram است؛ غلط املایی/مترادف/فیلتر پیچیده
  محدود است.
- **پیشنهاد:** Meilisearch/Typesense با ایندکس هم‌زمان و fallback به Postgres.
- **اثر:** متوسط-بالا (کشف کسب‌وکار) / **هزینه:** متوسط.

### ۲۰. جداسازی رسانه/CDN — وضعیت: معوق

- **مشکل:** رسانه روی همان سرور MinIO است؛ ترافیک تصویر با API شریک می‌شود.
- **پیشنهاد:** سرور رسانه/CDN جدا و بازنویسی `MINIO_PUBLIC_URL`.
- **اثر:** متوسط / **هزینه:** متوسط.

### ۲۱. دسترس‌پذیری (a11y) — وضعیت: پیشنهاد

- **مشکل:** ممیزی WCAG و ناوبری کیبورد انجام نشده.
- **پیشنهاد:** بررسی با axe، اصلاح کنتراست/فوکوس/برچسب فرم‌ها.
- **اثر:** متوسط / **هزینه:** کم-متوسط.

### ۲۲. ترجیحات اعلان کاربر — وضعیت: پیشنهاد

- **مشکل:** اعلان‌ها/پیامک‌ها بر اساس سوئیچ‌های عمومی‌اند، نه انتخاب کاربر.
- **پیشنهاد:** صفحه‌ی «اعلان‌ها» با کانال (درون‌برنامه/پیامک/بله) به‌ازای هر
  نوع رویداد.
- **اثر:** متوسط / **هزینه:** کم-متوسط.

### ۲۳. استقرار بدون قطعی (blue-green) — وضعیت: معوق

- **مشکل:** استقرار فعلی `docker compose up -d` است و ممکن است چند ثانیه قطعی
  داشته باشد.
- **پیشنهاد:** دو سرویس پشت nginx با health-check و سوییچ ترافیک.
- **اثر:** متوسط / **هزینه:** متوسط-بالا.

## پیشنهادهای کوچک و سریع

- افزودن `requestId` به پاسخ خطاها و لاگ‌ها.
- `Cache-Control: no-store` روی پاسخ‌های auth.
- صفحه‌ی «وضعیت سرویس» عمومی بر پایه‌ی `/api/health`.
- لینک «حریم خصوصی/قوانین» در فوتر و ثبت رضایت هنگام ثبت‌نام.
- تست دود (smoke) برای مسیرهای عمومی در CI با `curl`.
