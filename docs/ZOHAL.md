# سرویس‌های استعلام زحل

این سند نحوه‌ی اتصال پلتفرم به وب‌سرویس‌های **زحل** را توضیح می‌دهد. مستندات
رسمی: <https://dashboard.zohal.io/documents> و فهرست سرویس‌ها:
<https://dashboard.zohal.io/services>. قرارداد OpenAPI در فایل `api-1.json`
(خارج از مخزن) نگه داشته می‌شود.

> **هزینه:** هر فراخوانی واقعی از کیف پول حساب زحل کسر می‌شود. در تست‌های
> خودکار از یک سرور mock محلی استفاده کنید (بخش «تست بدون هزینه»).

## اتصال

| مورد | مقدار |
| --- | --- |
| آدرس پایه | `https://service.zohal.io` (قابل تغییر با `ZOHAL_BASE_URL`) |
| احراز هویت | هدر `Authorization: Bearer <ZOHAL_TOKEN>` |
| قالب | JSON (RESTful) |
| محدودیت IP | زحل فقط درخواست‌های IPهای اعلام‌شده در پنل را می‌پذیرد |

توکن فقط سمت سرور خوانده می‌شود و هرگز به مرورگر نمی‌رود. مقدار آن را در
`.env` سرور قرار دهید:

```env
ZOHAL_TOKEN=<token>
ZOHAL_BASE_URL=https://service.zohal.io
```

اگر توکن تنظیم نشده باشد، پنل «زحل» وضعیت «تنظیم نشده» را نشان می‌دهد و
فراخوانی‌ها با خطای ۵۰۳ رد می‌شوند.

### قالب پاسخ

```json
{ "result": 1, "response_body": { "data": { ... }, "message": "موفق", "error_code": null } }
```

`result`: `1` موفق، `4` درخواست نامعتبر، `5` خطای داخلی زحل، `6` خطای ورودی.

## فعال‌سازی ماژولار

همه‌ی ۳۵ سرویس در `apps/api/src/zohal/zohal.constants.ts` فهرست شده‌اند و
پنل مدیریت → «زحل (استعلام)» آن‌ها را گروه‌بندی‌شده نشان می‌دهد. هر سرویس یک
کلید تنظیمات مستقل دارد:

```
zohal.service.<key> = true | false
```

- پیش‌فرض فقط `shahkar` و `national_identity_inquiry` روشن‌اند (برای جریان
  تکمیل پروفایل و تیک آبی).
- بقیه‌ی سرویس‌ها پیش‌فرض خاموش‌اند و با سوییچ پنل روشن می‌شوند.
- سمت سرور، `ZohalService.assertServiceEnabled(key)` هنگام استفاده اعمال
  می‌شود؛ بنابراین خاموش‌بودن سوییچ حتی با فراخوانی مستقیم هم جلوی درخواست را
  می‌گیرد.
- دکمه‌ی «آزمایش» در پنل، سرویس را حتی وقتی خاموش است یک‌بار صدا می‌زند
  (`force`) و پاسخ خام زحل را نشان می‌دهد — این یک درخواست **واقعی و هزینه‌زا**
  است.

### گروه‌ها و سرویس‌ها

| گروه | نمونه سرویس‌ها |
| --- | --- |
| احراز هویت | شاهکار (تطابق موبایل/کد ملی)، استعلام هویت با کد ملی، OCR کارت ملی، استعلام شرکت، تطابق کارت/شبا با کد ملی، هیئت‌مدیره |
| احراز هویت ویدیویی | آپلود مدیا، Liveness، دریافت نتیجه |
| بانکی | استعلام کارت/شبا، تبدیل کارت↔شبا↔حساب، تطابق نام با کارت/شبا، چک برگشتی، چک صیادی |
| خدماتی | کد پستی، خلافی خودرو، اینماد، تبدیل نام فارسی به انگلیسی، قبض برق/گاز/آب/تلفن/موبایل، OTP صوتی |

## تکمیل پروفایل با استعلام هویت

جریان جدید (وقتی `featureIdentityInquiry` روشن و سرویس
`national_identity_inquiry` فعال است):

1. کاربر در «پروفایل» فقط **کد ملی** و **تاریخ تولد شمسی** را وارد می‌کند.
2. `PATCH /profile/me` با `{ nationalCode, birthDate }` سمت سرور
   `national_identity_inquiry` را صدا می‌زند.
3. اگر `matched=true` باشد، نام و نام خانوادگی برگشتی ذخیره می‌شود
   (`fullName` هم همگام می‌شود). نام هرگز از سمت کلاینت پذیرفته نمی‌شود.
4. اگر استعلام در دسترس نباشد (سوئیچ خاموش/توکن تنظیم‌نشده)، فرم به‌صورت
   خودکار ورودی دستی نام را نشان می‌دهد تا ثبت‌نام قفل نشود.

## تیک آبی

1. کاربر پس از تکمیل مشخصات هویتی، در پروفایل «درخواست تیک آبی» را می‌زند
   (`POST /profile/blue-tick/request`).
2. سرور یک‌بار هویت را با `national_identity_inquiry` بازبینی می‌کند (نیازمند
   موبایل تأییدشده) و درخواست را با `blueTickRequestedAt` ثبت می‌کند.
3. مدیر در پنل «زحل» درخواست را تأیید/رد می‌کند. تأیید `User.verifiedAt` را
   ست می‌کند و نشان «تأیید هویت» در پروفایل و صفحات عمومی بیولینک/کارت ویزیت
   نمایش داده می‌شود.

## تست بدون هزینه

برای تست محلی بدون کسر وجه، یک mock ساده روی شبکه‌ی داکر بالا بیاورید و
`ZOHAL_BASE_URL` را موقتاً به آن اشاره دهید:

```bash
# mock روی کانتینر web، پورت ۴۹۹۹
ZOHAL_BASE_URL=http://web:4999 docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d api
```

mock باید برای `national_identity_inquiry` پاسخ
`{ result: 1, response_body: { data: { matched: true, first_name, last_name, ... } } }`
و برای `shahkar` پاسخ `{ result: 1, response_body: { data: { matched: true } } }`
برگرداند. پس از تست، مقدار را به `https://service.zohal.io` برگردانید.

## فایل‌های مرتبط

- `apps/api/src/zohal/zohal.constants.ts` — فهرست کامل سرویس‌ها.
- `apps/api/src/zohal/zohal.service.ts` — کلاینت، سوییچ‌ها و جریان تیک آبی.
- `apps/api/src/zohal/zohal.controller.ts` — مسیرهای ادمین و کاربر.
- `apps/web/components/admin/AdminZohal.tsx` — پنل مدیریت «زحل».
- `apps/web/components/dashboard/ProfilePanel.tsx` — فرم استعلام/تیک آبی.
