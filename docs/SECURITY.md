# امنیت احراز هویت (Auth Security)

این سند تصمیم‌های امنیتی جریان ورود/ثبت‌نام و توکن‌ها را خلاصه می‌کند تا هنگام
تغییر کد، رفتار مورد انتظار مشخص باشد.

## رمز عبور

- رمزها با **bcrypt** و `SALT_ROUNDS = 12` هش می‌شوند (نمک برای هر رمز به‌صورت
  خودکار تولید می‌شود). هیچ‌جا رمز خام ذخیره یا لاگ نمی‌شود.
- هش رمز هرگز از API بیرون نمی‌رود؛ پروفایل فقط `hasPassword: boolean` را برمی‌گرداند.
- **ورود با ایمیل و رمز**: اگر ایمیل ناموجود باشد یا حساب رمز نداشته باشد، باز هم یک
  مقایسه‌ی bcrypt (با هش ساختگی) انجام می‌شود تا زمان پاسخ، وجود/عدم‌وجود ایمیل را لو ندهد.
- **تغییر رمز**: اگر حساب از قبل رمز دارد، ارسال `currentPassword` الزامی است؛ در غیر
  این‌صورت فقط با داشتن یک نشست دزدیده‌شده می‌شد رمز را عوض کرد.

## کد یکبار مصرف (OTP)

- فقط **هش SHA-256** کد در Redis نگه‌داری می‌شود (هرگز کد خام)، با TTL ۵ دقیقه،
  حداکثر ۵ تلاش و کول‌داون ۶۰ ثانیه‌ای برای ارسال مجدد.
- کدها با «نام‌فضا» (`login` / `phone-change` / `email-change`) جدا می‌شوند تا یک کد
  یک جریان قابل بازپخش در جریان دیگر نباشد.
- وقتی Redis سالم است فقط Redis منبع حقیقت است؛ پاک‌کردن کلید، کد را واقعاً باطل می‌کند.

## محدودیت نرخ (Rate Limit)

`apps/api/src/common/rate-limit.service.ts` روی Redis (با fallback حافظه‌ای) کار می‌کند و
قواعد پیش‌فرض `RATE_LIMITS` را اعمال می‌کند:

- ورود با رمز: ۱۰ تلاش / ۱۵ دقیقه به‌ازای هر IP.
- درخواست OTP: ۵ بار / ۱۵ دقیقه به‌ازای هر شماره و ۲۰ بار / ۱۵ دقیقه به‌ازای هر IP
  (محافظت از هزینه‌ی پیامک و جلوگیری از spam).
- تأیید OTP: ۱۰ تلاش / ۱۵ دقیقه به‌ازای هر شماره.
- ثبت‌نام: ۵ حساب / ۱ ساعت به‌ازای هر IP.

عبور از حد → پاسخ `429` با پیام «تلاش‌های بیش از حد…».

## توکن‌ها و نشست

- **توکن دسترسی (JWT)**: کوتاه‌عمر (پیش‌فرض `15m` از `JWT_EXPIRES_IN`)، الگوریتم
  `HS256`، با کلیم‌های `iss=alooshomal-api` و `aud=alooshomal-web` که هنگام بررسی
  اعتبارسنجی می‌شوند. توکن شامل `sid` (شناسه‌ی نشست) است.
- **رفرش توکن**: مقادیر تصادفی ۴۸ بایتی؛ فقط **هش** آن در جدول `Session` ذخیره می‌شود.
  در کوکی `HttpOnly` (`Secure` در پروداکشن، `SameSite=Lax`، `Path=/api/auth`) قرار
  می‌گیرد و در JS قابل خواندن نیست. هر بار رفرش، توکن **چرخش** می‌کند و توکن قبلی باطل
  می‌شود.
- **عمر نشست**: حداکثر ۳۰ روز، و اگر ۷ روز استفاده نشود به‌صورت خودکار بسته می‌شود
  (`SESSION_IDLE_DAYS = 7`). هر درخواست معتبر، `lastUsedAt` را به‌روز می‌کند.
- **ابطال نشست**: با `sid`، توکن دسترسی حتی وقتی امضایش معتبر است اگر نشست باطل/منقضی
  باشد رد می‌شود؛ پس خروج یک‌دستگاهی، «خروج از همه»، خروج اجباری ادمین و غیرفعال‌سازی
  حساب بلافاصله اثر دارند.
- `JWT_SECRET` در پروداکشن **الزامی و قوی** است؛ در غیر این‌صورت API بالا نمی‌آید.

## هدرها و مرورگر

- `helmet` برای هدرهای امنیتی و CORS فقط برای `CORS_ORIGIN`های مجاز با `credentials: true`.
- توکن دسترسی در `localStorage` است (کوتاه‌عمر)؛ توکن بلندعمر در کوکی `HttpOnly`.

## جریان زنده (SSE)

- `EventSource` نمی‌تواند هدر بفرستد، پس **هیچ‌وقت توکن دسترسی در URL قرار نمی‌گیرد**.
  به‌جای آن، کلاینت با یک درخواست احرازشده یک **تیکت یک‌بارمصرف ۳۰ ثانیه‌ای** می‌گیرد
  (`/notifications/mine/stream-ticket` و `/admin/notifications/stream-ticket`)، و استریم
  با `?ticket=` وصل می‌شود. تیکت در Redis با `GETDEL` در اولین استفاده مصرف می‌شود، پس
  حتی اگر در لاگ بیفتد دیگر قابل استفاده نیست.
